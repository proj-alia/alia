# 中文记忆检索固定评测 v1

`zh-v1.json`为合成留出集：20组主题，每组有旧认识、当前一般认识、当前局部例外及名字相近的其他人，共80条记忆和对应来源事件。100条人工编写查询分为当前事实、同义改述、历史时点、局部例外和一般/例外对比，各20条。它们共享20组基础情境，不是100个独立生活样本，也不代表真实用户历史。

当前版本的内容哈希见`zh-v1.sha256`。标注初审修正过旧来源文本的时态及局部scope与运行时event UUID的对应，尚未运行任何检索、选模型或调参。现在按该哈希固定；后续发现标注错误时另发v2并说明差异，不能根据检索结果直接改v1。完整性校验：

```sh
python3 scripts/check_retrieval_corpus.py
```

查询的`at`是检索参照时间；历史查询的`include_history=true`要求检索当时有效的旧认识，并明确显示它如今已被替代。默认当前查询不能使用已替代认识。局部scope使用对应来源的`event:<uuid>`，与一般scope并存。subject区分林澄与林晨，不能将名字相似视作同一人。

`relevant_ids`是应召回的记忆；`supplemental_ids`是允许作为对照的补充内容（如局部例外问题中的一般偏好），不作为错误命中；`forbidden_ids`是该问题不应当作答案依据的同主题错误来源。每题计算top10命中的相关ID数/全部相关ID数，再取100题宏平均，初始门槛0.9。错误人物、范围及时间单独计分，不得靠召回率掩盖。历史内容可以带有明确“已过时”标记展示，但不能据此把它用于当前结论；评测报告须区分原始检索和最终使用。

初始冻结时只交付标注与结构检查，数据文件中的not_run状态保留为冻结时元数据；实际运行结果另存报告。现已执行首个真实E5/PostgreSQL基线，Recall@10=1.0，但有93次近名人物的禁止原始命中，完整检索验收未通过。详见docs/EMBEDDINGS.md。M2需用实际嵌入和存储执行100题，保存原始排名、模型/索引版本、拒绝与遗漏原因。调参使用独立开发集，不能用本留出集反复挑选配置。人工/独立语义检查仍须补充，结构检查不证明标注或检索语义正确。
