# M2：共享记忆读取与验证

状态：工程接通与独立实验已完成；完整 M2 行为和来源质量验收未完成。实际发布及最后检查记录见 IMPLEMENTATION；此文不把候选命中当作正确回答。

## 运行方式与状态所有权

| 入口 | 实际来源 | 再检查 |
| --- | --- | --- |
| 对话/目标上下文 | 当前事件、目标及其作用域，最多1000字符作为检索串 | 重新组装上下文时验证身份/版本/隐私代次，所选记忆及完整来源进入 input_manifest |
| memory.search v3 | 已提交动作的 query、limit、可选人物UUID或精确姓名 | 编码前检查权限/租约/额度/前序动作；提交时检查同一参数摘要、解析来源与所选内容 |
| WebUI 服务端检索 | 闭合 API 参数，不改个体状态 | 同快照补充人物断言；结果说明实际模式、覆盖与非穷尽范围 |

ALIA_EMBEDDING_DIR 配置成功时，一个 CpuMemoryEncoder 由索引 worker 和查询 Store 共享；前台 worker 在注册后取得该 Store。没有第二套个体或另一份模型会话记忆。未配置为 lexical，已配置为 hybrid；编码错误返回明确失败，不静默切换成词项或空结果成功。

原始事件、当前认识及检索索引保持分开。工具成功结果仍是 generated 的存储认识集合；保存回执不能把其中的陈述升级为亲历事实。

## 过滤、排序和长输入

语义池、词项池和覆盖数量共用资格条件：当前个体、有效状态/时间、general或指定scope、关系对象条件、人物事实主体及当前版本断言、递归来源阻断。向量须匹配固定profile、memory_version、content_digest、privacy_epoch和完整块集合。

当前 `semantic-primary-unindexed-interleave3/1` 保留已索引候选的精确余弦次序。对没有当前完整向量集、且词项匹配的记录使用独立候补池，每三个语义结果后纳入一个；任一池为空时由另一池补足。这样新记录能在索引完成前被读取，普通词项出现次数也不会再次给已有语义候选投票。API最多返回20条，工具最多5条，上下文最多10条；非穷尽，不输出伪造的置信度。

短查询保持模型既有query前缀编码；超过原生token窗口的有效长查询按完整Unicode区间切窗、逐窗编码、求和并L2归一化。窗口都实际检查token长度，不依赖tokenizer静默截断。这是工程聚合启发式，不等同于原生长上下文理解。对话输入超过检索串限额时 `query_limited=true`，原始事件仍独立进入上下文。

依据：[E5作者模型卡](https://huggingface.co/intfloat/multilingual-e5-small)说明384维、query/passage前缀、池化归一化与512-token示例；本项目额外的跨窗口聚合需独立验证。[pgvector官方说明](https://github.com/pgvector/pgvector)提供精确余弦运算，不能保证实际语义或人物归属正确。

## 并发、故障与权限

- 编码不占数据库事务或写锁。只读状态读取与带行锁的写入状态读取分别实现。
- 读取后检查状态/隐私代次；放入上下文、公开投影或工具结果之前再次验证所选记忆正文、版本、范围、时效与完整来源。旧查询不能覆盖新消息后的状态。
- 工具参数和能力版本不能在等待期间更换。成功/失败、来源、调用计数和回执原子提交；缓存回执重放不再编码。递归撤销同样约束历史回执。
- person_id必须明确存在；工具还要求其已进入本轮可见引用/manifest。person_name与UUID互斥，逐字解析保存的有效姓名/别名；同名明确失败，未知不回退全库。事实主体与仅被提及分开，不自动把近名或同名合并。
- 查询等待10秒；信号量覆盖原生调用实际生命周期。异步取消不硬中断ONNX，也不允许晚到结果直接写回。
- memory.search已升级为v3；已完成v1/v2回执保持历史，旧待执行版本按能力不匹配处理，不静默重写意图。

## 人物定向读取与真实模型开发试验（2026-11-12 UTC）

现已增加姓名/别名定向读取：语义意图由正常认知步骤提出，程序按完整有效别名表精确解析；查询不创建人物、不合并近名，未知和同名均明确失败。姓名和UUID互斥，最大80字符；HTTP和工具复用同一路径。查询结果记录定位方式，解析依据进入来源图，零条记忆也保留人物解析的来源。最终提交重新验证绑定及注记，源撤销阻断回执重放。

模型上下文与工具现在收到每条记忆的实际人物角色和来源性质，主体与提及可以同时出现在一条记录中。未标注和截断保持未知，不从字面共同出现推断所有权。WebUI增加精确姓名查询，未知失败清空旧成功结果，继续显示非穷尽范围和真实覆盖。

工程证据：完整160项PostgreSQL套件通过，之后新增的目录23人/模型可见20人用例单独通过；51项普通Rust、默认及local-embeddings严格clippy、前端构建/组件/SSE、M0通过。新用例覆盖近名/未知较长姓名、两种编码模式、同名歧义HTTP422、工具失败计数、角色入上下文、别名来源撤销、零结果依赖及缓存不重算。当前脚本共包含161项DB用例，不把普通cargo test中的ignored算作已执行。

真实浏览器`person-query-web-v2/`的create/restore两阶段通过，覆盖姓名与UUID互斥、服务端精确定位、未知404无旧结果残留、六宽度及既有v4流程。初次浏览器检查只等“编辑”按钮出现，过早读取保存后的旧React视图；改为等待确认流程真正结束，并另查服务端值，未放松版本检查。保存刷新期间禁用再次编辑。失败日志`/tmp/alia-person-query-browser.log`保留。
