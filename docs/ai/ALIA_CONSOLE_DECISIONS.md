# ALIA Console v4 决策记录

| 决策 | 原因与实现 |
| --- | --- |
| 采用安装目录 v4，保留 tmp v2 | 已安装包与暂存包不是同一版本；不覆盖用户新资料 |
| 13 主入口、保留旧书签 | 认知/关系归入个体，交流归入渠道，追踪/事件归入数据；不是删除领域能力 |
| 延续 hash 路由和现有工程 | 不因原型路径示意替换路由栈、Rust 服务、REST/SSE 或个体状态所有权 |
| 配置分区与完整 JSON 共用同一草稿 | 防止存在两份可并行修改的状态；保留未显示字段。数值边界直接读取 runtime schema |
| 原文模式转分区先严格校验 | JSON.parse 会丢弃重复键；不能让结构化修改掩盖无效原文 |
| 未保存保护使用历史索引恢复 | 浏览器前后退也必须等待保存/放弃/取消；取消不丢草稿。空 JSON 仍属于修改 |
| 辅助色覆盖包内 #7b8395 | 小字号对比不足；采用 #626c7f，状态文字相应调整。其余主要尺寸、背景和主色延续 v4；深色是包外必要扩展 |
| 内置能力不伪装为已安装插件 | 安装、注册、授权和执行成功分别呈现；不把 Memory Core 当作可卸载身份基础 |
| 依赖页标明构建声明范围 | package.json 的直接运行依赖不等于全量解析树或插件更新状态；不从 UI 执行主机包管理 |
| 只读模型和渠道资源详情 | 暂无安全写接口时仍提供资源选择和真实状态；不接受无法安全保存的密钥，不用模拟写入填补缺口 |
| 生产个体不为截图而初始化 | 验收使用随机访问令牌、隔离数据库、无模型凭据；fixture 清楚标记来源 |
| v3 与 v4 证据分开 | v4 输出到独立结果目录，旧通过记录保留；原型 QA、产品工程测试和生命能力验收分别报告 |

完整背景见[审计](ALIA_CONSOLE_AUDIT.md)。
