## 任务目标

**必须推翻 v1/v2/v3 风格**：此前大面积紫色品牌渐变、圆角卡片展示墙和数字存在营销模块都不是要实现的控制台。v4 采用真实管理工具的简洁信息架构：参考 AstrBot 的配置分区、插件/Skills/MCP/日志入口；Koishi 的插件分组、市场/依赖表格、配置状态和沙盒。

保留 ALIA 的数字个体特性，但不让人格 / 记忆 / 关系信息挤占插件和模型管理操作界面。严格禁止任何动漫、角色、人物立绘、头像插画或装饰性背景。

## 开发方式

- 在当前仓库内审计后直接开发，而非创建仅用于展示的第二套独立 Demo。
- 先适配现有路由、状态管理与组件库。以 v4 原型为信息结构和行为参考，重写为本仓库技术栈的可维护组件。
- 以 M0→M6 逐阶段完成，不只写文档、不只生成效果图。
- API 未实现则明确显示「不可用/待接入」，不得伪装成功或制造在线状态。
- 所有写操作都必须先由服务端验证、授权并返回成功后才更新运行状态；危险操作需要二次确认和审计。
- 运行构建/测试/浏览器检查，每阶段提交验收结果，更新 `docs/ai/` 报告。
