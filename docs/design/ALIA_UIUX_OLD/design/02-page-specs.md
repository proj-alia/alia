# 十个页面的功能规格（UI/UX Source of Truth）

**默认宽度基准**：1440px 桌面 / 390px 手机。每页采用 `Sidebar + Topbar + PageHeader + Content`，默认亮色主题。右侧详情区在宽屏保持可见，在手机堆叠并支持返回到列表。数据为原型模拟。

## 01. 个体总览 `/overview`

**使用目的**：30 秒内理解个体当前运行态、身份连续性、最近活动和需要干预的事。

**结构**：Page Header（暂停自主行动）→ Identity Continuity 横幅（文字 + 结构关系）→ 4 KPI 卡（演示连续性、记忆条数、待审批、媒介连接）→ 双栏（最近事件/待审批）→ 信息架构导航图。

**交互**：导航到事件、审批详情、确认批准/拒绝、暂停/恢复；全部高风险点击都先弹框。不要使用不可追溯的「记忆健康 92%」或「意识强度」之类数字。

## 02. 身份与人格 `/identity`

**目的**：稳定主体标识，分离身份锚点、人格偏好、安全规则、修订版本。

**结构**：实体标识、创建时间、可替换模型说明、人格分层卡、版本历史。大字母 A 为识别标记，不是角色形象。

**交互**：提议修订，填写理由，显示待审核；不能静默写入最终人格。生产版修订需有作者、版本比较、回滚路径与后端回执。

## 03. 记忆档案 `/memory`

**目的**：查看“记住了什么、来源在哪里、是否可信、如何纠正”。

**结构**：分类 Tabs（全部/核心/语义/经历）+ 搜索 + 左侧结果列表 + 右侧 Memory Inspector（来源、证据状态、详情、修订/复核操作）。

**交互**：实时搜索并显示空结果；点击条目刷新详情；提议修订需原因；标记待复核提供反馈。历史版本不可无声覆盖。

## 04. 认知画像 `/cognition`

**目的**：区分当前观点、依据、认知局限、需要继续验证的假设。

**结构**：知识/认知观察信息卡、可检查来源的观点、认知限制和学习/验证计划。不可将抽象“意识”当作可测指标。

**交互**：查看假设依据、信息来源与更新条件；真实系统没有证据时用“暂无依据”代替编造分数。

## 05. 关系脉络 `/relations`

**目的**：记录不同主体及其可共享的共同事件、授权和边界。

**结构**：关系对象列表 + 右侧共同历史时间线/权限描述，时间节点显示日期与事件来源。

**交互**：切换关系对象立即更新详情；显示隐私与同意边界。无需引入“亲密度 +3”游戏化数字。

## 06. 意图与行动 `/agency`

**目的**：观察目标、任务、执行阶段和待审批的外部行动。

**结构**：目标信息、进行中的操作、待审批列表、失败/完成状态；每一待审批动作需能查看 target、scope、payload、risk。

**交互**：详情 → 批准/拒绝 → 二次确认 → 服务端回执。禁止通过前端 UI 直接执行实际工具调用。

## 07. 感知与媒介 `/media`

**目的**：查看当前连接渠道/设备，以及它们允许读取、写入、交互的能力。

**结构**：连接器网格（Web、浏览器、API、邮件、语音、设备），包括在线/离线/规划状态、授权范围与链接详情。

**交互**：查看媒介能力说明，区分可用/不可用/规划中；未经授权不能从状态显示页直接获得写权限。

## 08. 授权与治理 `/governance`

**目的**：明确哪些行为可自动执行、哪些需要审核、哪些被禁止。

**结构**：安全警告 + 能力权限矩阵 + 当前审批队列 + 防越权与审计说明。

**交互**：权限模式 `auto | approve | deny` 的切换是**策略变更请求**，UI 显示二次确认、待服务端验证结果；不能修改下拉框后直接视为授权成功。

## 09. 事件回溯 `/events`

**目的**：按时间、事件类型、操作者或关联对象还原“发生了什么”。

**结构**：事件列表、搜索/过滤、可检视详情和导出操作。事件包含 `eventId`, `occurredAt`, `actor`, `kind`, `resourceId`, `traceId`。

**交互**：关键词检索；用户选择导出；真实审计需要不可由前端静默篡改的服务端日志。

## 10. 运行与设置 `/settings`

**目的**：查看运行环境、当前模型连接、数据源状态与个人界面偏好。

**结构**：运行环境信息、API 连接状态、当前主题、演示/真实模式声明、状态导出。

**交互**：主题切换即时生效；导出仅包含 UI 数据（生产环境仍需服务端授权）。不得在页面展示 API Key/Token 明文。

## 通用状态矩阵（10 页都适用）

| 状态 | 必须呈现 | 用户可做什么 |
|---|---|---|
| Loading | 卡片骨架、区域占位和状态文本 | 等待，可取消时允许取消 |
| Empty | 清楚说明为空的原因与下一步 | 刷新、创建或调整过滤 |
| Error | 非敏感错误原因、重试按钮 | 重试、返回 |
| Unauthorized | 403 提示、所需范围 | 请求授权，不泄露数据 |
| Disconnected | 连接断开、最后成功同步时间 | 重连/刷新，不伪造在线 |
| Conflict | 409 版本冲突、最新版本摘要 | 刷新后重试，不覆盖新数据 |
| Success | 对应服务端回执、状态更新时间 | 继续下一步 |

**重要**：原型只演示其中可在离线条件下完整模拟的交互；上述 Loading / 403 / 409 等属于生产实现必须补齐的验收要求。
