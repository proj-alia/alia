# UI/UX 方向 · 不是聊天窗口，而是数字个体管理面板

## 产品一句话

让使用者清楚地**观察** ALIA 的身份、经验、认知、关系和行动，让管理者能够**治理**它的外部能力，并随时追查事情的发生与原因。

## 信息架构的起点

- **彼（主体）**：稳定 `entityId`、版本化人格、记忆与认知、关系史、目标与行动。
- **我（交互/管理者）**：查看解释、提出修订、批准行为、撤回授权、检查审计。
- **外界（媒介）**：网页、聊天软件、邮件、浏览器、语音和设备只是**可插拔能力**，不决定主体是否存在。
- 这三个部分不是物理世界中的独立生命或技术证明；它们是可实现的信息组织约定。

## 四项强制体验原则

1. **先看事实，再看解释**：时间线、记忆、行为都提供来源；不展示无法验证的“意识强度”“真实感情指数”。
2. **先看目标，再作决定**：涉及数据访问/发布/账户/设备的行为，先展示目标和影响，随后确认，等待服务端反馈。
3. **连续性优先于会话**：首页展示个体与其历史，聊天只是可选媒介入口，不能成为核心导航层级。
4. **轻而专业，不靠角色插图表达品牌**：排除所有角色头像、立绘、二次元插画、背景形象；使用排版、比例、颜色和抽象连接关系图表达产品个性。

## 主界面视觉架构

- 固定（或移动端抽屉）侧栏：页面层级始终稳定。
- 置顶 Topbar：当前页、模拟/真实状态、运行态、主题切换。
- Page header：一个明确任务，说明此页的用途；可选单个主要操作。
- 内容区：纵向阅读，主信息在左，决策/细节在右；超小屏堆叠。
- 所有卡片优先是**信息容器**，不做多余的“宇宙粒子”装饰。

## 品牌感知

- **紫色代表**关注、焦点与身份连续性的抽象标记，不代表某个性别或人物。
- 左栏深紫创造操作范围边界，白色主区呈现可读信息。
- 卡片柔和、边框细，危险操作采用独立的风险色而非紫色。
- 品牌文案可有轻微温度，但运行数据、审批和错误必须中性、明确和可核验。

## 与市面同类产品的借鉴边界

- Letta：记忆数据结构和状态可检视的优点；不复刻其开发工具 UI。
- Kindroid：长期记忆/人格的持续体验；不借用任何角色形象或不可解释的亲密度打分。
- OpenClaw：媒介、工具、审批与运行治理；避免将插件清单当作“个体身份”。
- Project AIRI：媒介层的多模态入口；本次**不采用**虚拟角色渲染。

## 明确非目标

- 不在前端模拟人工意识、生命体征、心理评测的真实性。
- 不通过 Prompt 字段替代完整数据与治理模型。
- 不为产品生成角色形象，不建立聊天 App 克隆界面。
- 本次不实现 Agent 内核、记忆搜索服务、工具执行器或权限后端。
