# 受管模型预算：Go / GLM-5.3-Flash

2026-11-11，范围为文本 Chat Completions。本文是提供方计数契约与验证记录，不是所有云端服务的费用保证。

## 已开放的路径

仅 `opencode_go` + `https://opencode.ai/inference/go/openai/v1/chat/completions` + `glm-5.3-flash` 使用本计数配置。不同模型、其他网关或端口、DeepSeek 路径仍返回 `unverified_token_bound`。`ready` 表示该适配器可以进入受管调度，不保证凭证一直有效、服务在线或模型行为已全面达标。

请求仍是两个文本消息：系统规则与嵌入的提案 schema，以及序列化后的领域上下文。没有原生工具声明、图像、音视频、远端历史引用或多候选生成。`reasoning_effort=low` 降低不必要的生成；`max_tokens` 限定输出，JSON mode 约束返回格式。改变消息结构或增加媒介前必须重新验证计数配置。

## 依据与计算

当前有两个显式配置：未设置`ALIA_TOKENIZER_PATH`时使用`glm-utf8-bound/2`字节上界；配置已验证模型文件时使用`glm-pinned-text/1`，对完整固定模板分支作本地精确计数。二者仅适用于上述同一提供方/端点/模型与两条文本消息形状。配置了损坏或不兼容的模型文件会启动失败，不静默回退。

精确配置固定Rust `tokenizers=0.22.2`及下表SHA256；最大文件32MiB，禁止padding/truncation。系统文本加用户文本最多256KiB，固定低推理级别和生成前缀，编码包含角色及控制token。计数失败或未经验证请求形状拒绝调用；审查和行动请求各自按实际正文计数。运行时不下载资产，安装入口为`scripts/install_tokenizer.py`，原子写入前核对哈希，Compose可选覆盖`compose.go-tokenizer.yaml`只读挂载。

本地精确计数不等于证明远端内部配置相同。供应商多计一个token也仍按超额处理；以下托管一致性假设、真实用量结算和冻结规则同样适用。

[官方模型仓库](https://huggingface.co/zai-org/GLM-5.3-Flash/tree/46a050bec13002ad29ee795c16e61cf4fa3c4a9c)的 tokenizer 无 normalizer，采用无前缀插入的 ByteLevel BPE，词表包含完整256字节映射；合并不增加 token 数。特殊 token 消耗非空文本，后处理只处理字节偏移。由此，本地该版本纯文本编码的 token 数不超过 UTF-8 字节数。

模型文件固定版本与 SHA256：

| 文件 | SHA256 |
| --- | --- |
| tokenizer.json | 19e773648cb4e65de8660ea6365e10acca112d42a854923df93db4a6f333a82d |
| tokenizer_config.json | 98b1271574f41abf89427ae2dda030d94dc9478f0edc5a8bd240db213c6fd5fc |

未安装tokenizer时，输入预留为**实际发送 JSON body 的 UTF-8 字节数 + 82**。固定模板在恰好两条 system/user 纯文本消息、无工具、开启生成前缀时，输出由消息正文与固定封装组成；低/最大推理级别封装81字节，高级别82字节，统一预留82。校验脚本对33组文本及三种级别逐项断言完整渲染结果与该闭式表达一致，而不只比较平均token比例。JSON正文长度不小于两条消息原文UTF-8长度。适配器拒绝附加工具、非文本内容、额外消息和未经核对的请求字段；构造正文的同一函数用于预留与发送。凭证和会话头不进入提示词。

此前使用整份模板源码10,830字节作为封装预留；下表早期试验仍保留当时的实际预留数，不能当作当前公式输出。此收紧依赖公开固定模板的分支检查，托管网关一致性限制与超额冻结机制保持不变。

[Z.AI Chat Completion 文档](https://docs.z.ai/api-reference/llm/chat-completion)定义 `max_tokens` 为输出 token 限制；[Go Inference 文档](https://opencode.ai/docs/console/api/inference/)说明响应报告用量，计费 output 包含 reasoning。Alia 保留总输入和总输出的实际 usage，不将缓存折扣或未展示推理当成免费 token。没有可验证 usage 时按完整预留结算。

## 适用限制

公开 tokenizer/template 的推导**不能证明托管网关内部完全一致**，也无法证明供应商未来不会更换模型或封装。本次开放基于指定模型的公开实现、API输出约束和实际请求兼容性证据。它是有来源的保守提供方契约，非远端计费系统的形式化证明。官方目前未公开 Go 请求前计数接口；[官方仓库的功能请求](https://github.com/anomalyco/opencode/issues/58270)仍开放。

应用按预留阻止超过每日额度的新调用；真实输入或输出超过预留时，已有结算路径记录实际量、拒绝提交提案并持久冻结该个体预算。已发出的远端调用无法被事后撤回，所以若供应商违反这份契约，不能声称本次远端费用仍被绝对限制。模型切换不自动沿用此配置。后续提供官方完整请求计数接口时优先替代；大上下文因保守预留而暂缓属于可见资源等待，不应通过虚报计数解决。

## 已运行的验证

`requirements-budget.txt` 是可选研究检查依赖，不加入服务运行时。`scripts/check_model_budget.py` 校验固定 SHA256、编码结构和字节词表，并使用官方 tokenizer 和模板执行33组文本、99组封装检查，均通过；含中文、组合Unicode、控制字符、emoji和特殊token字样。下载文件只存临时缓存，不提交模型资源。

Rust单元用例覆盖实际wire body长度、Unicode/转义、输出上限、上下文大小和未验证路径拒绝。既有数据库测试继续验证并发额度、未知费用、超额冻结、超时恢复，不用这次模型探测替代故障测试。

真实试验使用 `.tmp.env` 中明确的 Go 凭证段，只通过进程环境传递。`scripts/test_live_individual.py`创建专用临时数据库、运行三个独立Rust进程，每轮创建新的提供方会话ID；三个进程共用持久个体。执行真实worker、预算预留、模型调用、提案校验、记忆与回复提交，最后删除测试数据库。测试不用fixture、不启动持续后台、不修改生产个体。

最终试验合计16,663 token，每轮一次实际模型调用，全部正常结算，无冻结。此前同默认会话的三轮试验消耗16,326 token，也通过；最终试验额外排除了依赖同一提供方会话延续的可能。报告位于忽略版本控制的 `evals/results/live-individual-fresh-sessions.json`，公开汇总只保留测试数据和计数。

这些证据支持三个样例的工程/行为观察。它们没有证明中文召回率、60例多轮行为门槛、完整自主探索、人格成长或十四天真实运行已经完成。M1-07与项目Goal继续进行。

开放目标审查复用同一已核对的计数配置，但按自己的独立请求正文预留；没有免计费的审查通道。执行提示中的decision schema现在采用等价的紧凑JSON序列化，原schema约13,663字节，紧凑约5,954字节；只删除排版空白，不删验证约束。字节上界始终针对最终HTTP正文重新计算，不沿用压缩前的固定预留值，第一轮仅压缩schema，仍保留当时10,830字节模板预留；随后才按上述固定分支验证收紧至82。原因是一次真实试验在后台已有7,432token实际用量时，下一请求的保守预留无法容纳于50,000token余额；程序正确进入budget等待。该失败记录保留为evals/results/live-autonomy-budget-wait.json，不计通过。

后续真实自主试验：第二次已获得独立审查met意见，但最终行动请求因旧保守预留不足而等待，未完成目标（31,032 token）。第三次使用82字节封装，公开33/99例检查与Rust单元通过；真实调用两次消耗8,622 token，因模型提案被拒而停止，未形成目标。来源报告分别为live-autonomy-review-met-budget-wait.json和live-autonomy.json；均不计自主闭环通过，未写生产历史。


2026-11-12进一步证据：带诊断的自主试验32,825token，引用格式失败后预算等待；完整联合试验51,642token（后台25,490），初次阅读/偏好及重启例外已提交，后台输出截断/验证失败后预算等待。联合试验最后已发送请求的公开字节上界25,589，而供应商实际输入6,948；后台余额24,510不足以预留下一请求。此结果说明现有安全上界过度保守会限制实际可用性，不说明可以绕过预算。下一项是固定公开tokenizer/模板的本地精确计数、形状/哈希拒绝与实际计费回归；尚未实现，不声称M1通过。两次试验均未触碰生产数据。
