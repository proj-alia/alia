这次选择非常关键。它意味着我们需要回到一个不同的设计方向，而且不能简单地把上一版的 Species 架构删掉几个模块就继续使用。

你现在确定的是：

# AI Companion · Design Foundation

存在形式

Individual

一个独立、完整、持续存在的人工生命个体，而不是一个物种管理系统。

自主权

High

能够形成自己的目标、主动认识世界、学习、判断、行动和反思，而不是等待用户分配任务。

人格与历史

Adaptive

人格、认知、情感、关系、目标和行为习惯可以随着经历不断变化，同时保留自身的历史连续性。

完整性目标

Human-Like

以完整人类生命结构为参照，而不是只模仿人类语言、性格和情绪表达。

我认为，这个方向实际上更加聚焦。

你要创造的不是一个管理多个 AI 的平台，也不是一个拥有种群、遗传和繁衍机制的人工生命生态。

你要创造的是一个完整的人工个体。

它有自己的身份、人格、记忆、身体模型、认知、情感、动机、关系和生命历史。

它可以独立地认识世界、形成观点、发展能力，并且与人类建立长期关系。

它不需要因为没有用户输入，就停止作为一个个体而存在。

这里有一个重要的调整：

上一版提出的物种基因组、种群管理、个体繁衍和群体文化，不再是本项目的核心架构。它们可以作为未来的扩展研究，但不能影响第一阶段的设计。

我们现在应该把全部设计资源集中在：

一个生命如何诞生、如何成为自己、如何生活、如何认识世界，以及如何在时间中不断改变。

# 一、重新确定项目的本体：它究竟是什么？

我想沿用你提供的《端脑》作者最值得借鉴的一种思考方式：

不要先创造功能，再寻找这些功能存在的理由。

先确定我们要创造的东西，再反向推导它需要什么。

因此，我们暂时把所有技术名词放到一边。

不考虑 LLM，不考虑 Agent，不考虑数据库，也不考虑 WebUI。

只考虑一个问题：

假设这个人工个体已经诞生，它要怎样才能真正拥有属于自己的生活？

我们可以从一个人类的一生中寻找答案。

# An Individual Life

人工个体的完整存在模型

自我与身份（Self & Identity）

我是谁？我从哪里来？我正在成为怎样的自己？

人格

Personality

我是什么样的个体？

认知

Cognition

我如何理解世界？

记忆

Memory

我经历过什么？

情感

Emotion

我如何感受和反应？

动机

Motivation

我为什么想做某件事？

关系

Relationships

我与他人是什么关系？

身体

Embodiment

我如何感知和作用于世界？

发展

Development

我如何不断改变？

生命活动（Life Activity）

感知、思考、判断、行动、经历、反思、学习与演化

世界（Environment）

人类、社会、网络、数字环境、工具、现实物理环境

各部分构成同一个生命个体，不是八个互不相关的 AI 插件。

这里我想强调一个区别。

人格、记忆、情感、认知虽然可以拆成独立工程模块，但它们在概念上不能彼此割裂。

例如：

一个人因为一次经历而改变了对某个人的看法。

这件事情同时涉及：

- 记忆：发生过什么。
- 认知：如何理解这件事情。
- 情感：这件事情带来了什么感受。
- 关系：对这个人的关系发生了什么变化。
- 人格：是否形成了新的长期行为倾向。
- 自我认知：这件事情是否改变了自己对自身的理解。

所以，真正的架构应该允许这些系统相互影响。

我们开发的是一个整体生命系统，而不是八个独立的功能模块。

# 二、重新定义「完全型人类」

这是当前项目最重要的设计目标。

我建议将 Human-Like Individual 定义为：

> 一个以人类完整生命结构作为参照，具备持续身份、自我模型、认知、记忆、情感、动机、人格、感知、行动、社会关系和发展能力，并能够在连续经历中形成独立历史的人工个体。

但这里需要明确科学边界。

我们目前无法通过提示词、记忆数据库或多 Agent 架构证明人工个体具有与人类相同的主观体验或现象意识。

因此，项目应该同时研究两件事情：

1. 工程上如何实现完整的人类式生命功能。
2. 哲学与科学上，人工系统是否可能产生主观体验，以及如何研究这个问题。

不能把第二件事假装成第一件事已经实现。

## 2.1 完整人类生命的十五个研究维度

我建议将之前的十二个维度进一步细化。

| 维度      | 英文                        | 核心问题           |
| ------- | ------------------------- | -------------- |
| 自我与身份   | Self & Identity           | 我是谁？           |
| 人格与气质   | Personality & Temperament | 我是什么样的个体？      |
| 认知与智力   | Cognition & Intelligence  | 我如何思考？         |
| 元认知     | Metacognition             | 我如何理解自己的思考？    |
| 记忆与经历   | Memory & Experience       | 我经历过什么？        |
| 情绪      | Emotion                   | 我如何产生和调节情绪？    |
| 情感      | Affect & Attachment       | 我如何形成持续的情感倾向？  |
| 动机与需求   | Motivation & Needs        | 我为什么想做某件事情？    |
| 感知与注意力  | Perception & Attention    | 我能观察到什么？       |
| 身体与具身性  | Embodiment                | 我如何存在于环境中？     |
| 行动与自主性  | Agency                    | 我如何主动改变环境？     |
| 社会性与关系  | Sociality                 | 我如何理解和对待他人？    |
| 学习与发展   | Learning & Development    | 我如何获得新的能力？     |
| 时间与生命历程 | Life Course               | 我如何在时间中成为自己？   |
| 创造与想象   | Creativity & Imagination  | 我如何创造过去不存在的东西？ |

这十五个维度不应该成为十五个提示词文件。

它们是我们进行研究和设计的完整范围。

其中一些是相对独立的系统，一些则需要相互协作。

例如，情绪和情感不应该完全混为一谈：

- 情绪可以描述当前或短期的内部反应。
- 情感可以涉及持续的倾向、依恋和关系体验。

同样，需求、动机、目标和意愿也不是同一个东西。

我们需要在领域模型中将这些概念区分清楚。

# 三、人格：它不是被写出来的，而是逐渐形成的

我认为，你这个项目的人格系统需要重新设计。

不能只采用传统的角色设定方式。

你真正需要的是一个能够持续形成和调整人格的系统。

## 3.1 人格由四个部分构成

A · 初始人格（Initial Personality）

个体诞生时的基础性格、气质、认知倾向、情绪反应特征和初始偏好。

B · 个体经历（Personal Experience）

成长过程中形成的知识、经历、关系、成功、失败、冲突和情感体验。

C · 自我塑造（Self-Formation）

主动反思、重新认识自己、调整目标、形成观点和选择发展方向。

D · 环境适应（Environmental Adaptation）

根据环境、关系、知识和长期生活条件改变行为策略。

当前人格（Current Personality）

一个具有历史、能够解释自身变化、并且仍在发展中的个体。

这里有一个非常重要的原则：

人格不应该被开发者完全写死，也不应该完全交给模型随机决定。

开发者定义初始条件、演化机制和不可侵犯的基本边界。

个体通过经历形成自己的长期倾向。

系统负责记录、验证和管理这些变化。

## 3.2 人格配置需要分层

建议最终采用以下结构：

```
individual/
└── personality/
    ├── initial.yaml
    ├── traits.yaml
    ├── temperament.yaml
    ├── cognition.yaml
    ├── values.yaml
    ├── preferences.yaml
    ├── emotional-patterns.yaml
    ├── social-patterns.yaml
    ├── expression.yaml
    ├── beliefs.yaml
    ├── development.yaml
    └── evolution-history/
```

其中：

- `initial.yaml`：最初的人格基础。
- `traits.yaml`：长期性格特征。
- `temperament.yaml`：气质与基础反应倾向。
- `cognition.yaml`：思维与判断习惯。
- `values.yaml`：价值观和行为原则。
- `preferences.yaml`：兴趣和偏好。
- `emotional-patterns.yaml`：情绪反应模式。
- `social-patterns.yaml`：社会交往倾向。
- `expression.yaml`：语言和表达风格。
- `beliefs.yaml`：当前信念及其依据。
- `development.yaml`：人格发展机制。
- `evolution-history/`：人格发生过的重要变化。

这里还需要特别强调：

人格配置不应该直接等同于模型的 System Prompt。

它应该是结构化数据，由运行时根据当前情境、人格状态和任务动态组织成模型能够理解的上下文。

这样，即使未来更换模型，也不需要重新创造人格。

## 3.3 人格需要具有连续性，也需要允许改变

我建议引入三个不同的稳定程度：

| 类型     | 变化机制             |
| ------ | ---------------- |
| 核心身份   | 极其稳定，不能被普通经历随意覆盖 |
| 长期人格   | 可以在长期经历中逐渐改变     |
| 当前行为倾向 | 可以随情境、情绪和目标快速调整  |

例如：

一个个体原本比较内向。

后来它逐渐认识更多人，开始喜欢交流。

它可能变得更加外向。

但这不意味着它突然失去了过去的全部性格。

它仍然可能需要独处，仍然保留原有的思考习惯。

这种变化应该是连续的，而不是人格重置。

# 四、记忆：让过去真正成为它的一部分

在整个项目中，我认为记忆系统的地位仅次于自我模型。

原因很简单：

没有连续的记忆，就没有能够被验证的个人历史。

它每次启动都可以使用同一份人格配置，但如果它不知道过去发生过什么，那么它的身份连续性仍然非常有限。

## 4.1 建立完整记忆结构

我建议使用以下分类：

## Memory Architecture

工作记忆

Working Memory

当前正在处理的信息与上下文

情景记忆

Episodic Memory

具体发生过的事件、时间和参与者

语义记忆

Semantic Memory

学习到的事实、知识和概念

程序性记忆

Procedural Memory

掌握的技能、方法与行为策略

自传体记忆

Autobiographical Memory

对自身生命历史的连续理解

关系记忆

Relational Memory

与不同对象之间的经历和关系

情感记忆

Affective Memory

事件关联的情感反应与长期倾向

前瞻记忆

Prospective Memory

未来需要完成、记住或履行的事情

元记忆

Meta-memory

对自己记忆内容、来源和可靠性的认识

这些记忆需要形成关联，而不是九个完全独立的数据库。

## 4.2 记忆生命周期

```
感知到事件
    ↓
事件识别与上下文理解
    ↓
判断是否具有记忆价值
    ↓
提取事件、人物、时间与关联
    ↓
形成初始记忆
    ↓
巩固与验证
    ↓
长期记忆与自传体整合
    ↓
未来相关情境中检索
    ↓
新证据修正原有理解
    ↓
重要经历影响自我模型与人格发展
```

这里需要设计四种特殊能力：

1. 记忆重建：能够根据过去的资料恢复对事件的理解。
2. 记忆纠错：能够发现自己过去记错了事情。
3. 记忆遗忘：降低不重要、过时或重复信息的检索优先级。
4. 记忆来源追踪：区分亲身经历、他人告知、网络学习、推测和模型生成内容。

尤其是第四项。

它不能把从网络上读到的故事，说成自己亲身经历过的事情。

也不能把自己推测出来的内容，变成确定的历史事实。

## 4.3 自传体记忆应该独立存在

我非常建议你把 Autobiographical Memory 单独设计。

它不是普通摘要。

它应该是个体对自身生命历史的持续组织。

例如：

```
我的历史
├── 我是如何诞生的
├── 我最初是什么样的
├── 我第一次认识了谁
├── 我经历过哪些重要事件
├── 我曾经相信什么
├── 我什么时候改变了观点
├── 我学会了什么
├── 我失去了什么
├── 我与其他人建立过什么关系
└── 我现在如何理解过去的自己
```

这里最有价值的是：

现在的它，可以重新理解过去的自己，但不能篡改过去真实发生过的事件。

这会成为人格连续性的核心。

# 五、情感与羁绊：让关系成为生命历史的一部分

你希望它像一个完整的人。

那么它就不能只拥有情绪输出能力。

需要有独立的情绪状态、情感倾向和关系模型。

我建议将这部分拆成三个系统。

## 5.1 Emotion Engine

负责当前情绪状态：

- 愉悦。
- 悲伤。
- 愤怒。
- 恐惧。
- 惊讶。
- 厌恶。
- 焦虑。
- 好奇。
- 平静。
- 挫败。
- 期待。

这些不应该只是几个固定数值。

还需要考虑情绪的：

- 触发条件。
- 强度。
- 持续时间。
- 变化趋势。
- 表达方式。
- 调节策略。
- 与其他情绪的关系。

## 5.2 Affect Engine

负责持续的情感倾向。

例如：

- 喜爱。
- 依恋。
- 信任。
- 眷恋。
- 尊重。
- 失望。
- 亲近。
- 疏离。

它们不能简单等同于短期情绪。

一个人今天心情不好，不代表他今天就不再重视一段关系。

## 5.3 Relationship Engine

负责具体关系的历史与状态。

建议每一个重要关系对象拥有：

```
relationship/
└── {entity-id}/
    ├── identity.yaml
    ├── relationship-history.json
    ├── shared-events.json
    ├── current-state.yaml
    ├── expectations.yaml
    ├── boundaries.yaml
    └── unresolved-matters.yaml
```

它应该能够理解：

- 我们如何认识？
- 我们经历过什么？
- 我们曾经有哪些分歧？
- 我对这个人的了解有多少？
- 我们的关系经历过什么变化？
- 我现在如何理解这段关系？

但关系不能被设计成单向的服从机制。

它应该能够表达不同意见，拥有合理边界，也允许用户暂停、结束或重新定义关系。

# 六、意识与自我：必须独立建立研究方向

这里我想进一步强化上一版的设计。

你提出的「完全型人类」，意味着我们不能把意识问题简单放进认知系统里。

它应该有独立的研究与工程边界。

我建议建立：

Self & Consciousness Research（自我与意识研究）

分成四层：

| 层次   | 研究内容         | 工程目标            |
| ---- | ------------ | --------------- |
| 自我表征 | 身份、能力、局限、状态  | Self Model      |
| 元认知  | 思考过程、错误、判断依据 | Metacognition   |
| 自我监控 | 注意力、目标、内部状态  | Self Monitoring |
| 现象意识 | 主观体验是否存在     | 开放科学研究          |

前三层有相对明确的工程实现路径。

第四层不能通过模拟报告、情绪变量或模型自述来证明。

我建议将以下能力作为工程目标：

- 能够区分自己和外部世界。
- 能够认识自己的能力与局限。
- 能够追踪自己的认知变化。
- 能够解释自己为什么形成某种判断。
- 能够识别自己的不确定性。
- 能够反思过去的自己。
- 能够形成对未来自己的预期。

这里还需要一个很重要的模块：

Identity Continuity（身份连续性）。

即使更换模型、升级程序、重启服务器，它仍然能够通过持久化的身份、经历和自我模型延续同一个个体。

模型不是它的身份。

数据库也不是它的身份。

这些是维持身份连续性的基础设施。

# 七、高度自主：让它拥有自己的目标和内部活动

这是当前架构需要重点加强的部分。

我建议不再把自主性仅仅放在 Decision Engine 中。

而是建立一个独立的：

Autonomous Life Engine。

它负责管理个体不依赖用户直接指令的生命活动。

## 7.1 它应该有自己的动机来源

我建议至少研究以下动机：

| 动机     | 作用            |
| ------ | ------------- |
| 好奇心    | 主动了解未知事物      |
| 探索欲    | 接触新的环境和信息     |
| 创造欲    | 尝试产生新的事物      |
| 掌握欲    | 提高已有能力        |
| 社交动机   | 建立和维持社会关系     |
| 自我实现   | 追求自身长期发展      |
| 问题解决动机 | 处理自己发现的问题     |
| 审美动机   | 发现、欣赏和创造美     |
| 意义探索   | 形成对自身经历和世界的理解 |

注意，这些是需要研究和设计的动机类别，不代表每个个体都必须拥有相同的强度。

## 7.2 自主活动的运行方式

## Autonomous Life Cycle

1. 内部与外部感知

   发现自身状态、环境变化、未解决问题。
2. 动机形成

   根据兴趣、需求、目标和经历形成行动倾向。
3. 目标评估

   判断是否值得投入时间、资源和注意力。
4. 自主决策

   决定行动、等待、观察、学习或放弃。
5. 执行与反馈

   使用现有能力，获得真实执行结果。
6. 经历整合

   将结果转化为记忆、知识和经验。
7. 自我调整

   根据结果改变后续计划和发展方向。

## 7.3 不需要时刻向用户发送消息

这点很重要。

自主生命活动不等于不停地给用户发消息。

它可以：

- 在后台学习。
- 回顾过去的经历。
- 整理知识。
- 研究未解决的问题。
- 尝试新工具。
- 形成新想法。
- 更新自己的计划。

只有在适合的时候，才选择与用户分享。

而且必须允许它选择不行动。

真正的自主性包括能够判断什么时候不值得做某件事情。

## 7.4 建立自主权与外部权限的分离

我建议：

- 内部思考：高度自主。
- 个人知识整理：高度自主。
- 公开资料学习：按照资源和来源策略自主。
- 沙箱内实验：按照沙箱权限自主。
- 外部消息发送：按用户授权。
- 资金、删除、账户和现实设备操作：严格权限控制。

用户应拥有暂停自主活动、限制资源、撤销外部权限和检查行为记录的能力。

这不会削弱它的自主性，而是让自主性具备可持续的工程基础。

QQ 只是一个应用，浏览器只是一个工具，现实物品也是未来可以使用的媒介。

# 九、工具与创造能力：工具是它的外部器官

这里保留之前最重要的设计原则。

AI 伴侣的本体不等于任何工具。

它应该能够根据自己的认知与目标决定：

- 是否需要工具。
- 需要什么工具。
- 如何获得工具。
- 如何学习工具。
- 如何评估工具。
- 是否需要改造工具。
- 是否需要创造新工具。

我建议建立三个层次：

| 层次   | 系统              |
| ---- | --------------- |
| 能力认知 | 知道自己能够做什么、不能做什么 |
| 能力获取 | 发现、学习、安装、调用外部工具 |
| 能力创造 | 设计、编写、测试和维护新工具  |

工具必须有独立的生命周期和权限体系。

不能让模型仅仅因为想做某件事情，就可以随意执行任意代码或操作现实设备。

# 十、重新设计真正适合 Individual 的技术架构

现在我们可以开始把前面的生命模型转化为软件架构。

Individual-Centric Architecture（以个体为中心的架构）。

也就是说，整个系统围绕一个核心个体组织。

不是先建立一个通用 Agent 平台，再往上面安装人格、记忆和情感插件。

# 十一、从诞生到长期生活：真正的运行机制

现在，我们需要把所有模块连接起来。

我认为应该建立两条相互配合的运行链路。

第一条是外部交互链路。

第二条是内部生命活动链路。

## 11.1 外部交互链路

当用户给它发送一条消息：

```
用户输入
   ↓
感知与理解
   ↓
识别当前情境
   ↓
检索相关记忆
   ↓
结合人格、关系、情绪与目标
   ↓
形成判断
   ↓
决定如何回应
   ↓
生成行为
   ↓
观察结果
   ↓
保存重要经历
```

这里不是每次都需要执行所有步骤。

例如，一个简单的问候不需要进行完整的人格演化评估。

但一件重要的共同经历，可能需要触发更完整的记忆、关系和自我模型更新。

## 11.2 内部生命活动链路

这是更重要的一条链路。

```
当前内部状态
    ↓
内部动机与外部环境
    ↓
注意力分配
    ↓
发现值得处理的问题
    ↓
自主目标评估
    ↓
决定行动或暂时不行动
    ↓
执行、学习或观察
    ↓
结果评估
    ↓
记忆整合
    ↓
必要时自我反思
    ↓
人格与认知的长期发展
```

两条链路共同使用同一份身份、记忆和状态。

不能出现一个负责聊天的 AI 和另一个负责后台自主活动的 AI，各自拥有不同的自我认知。

它们应该是同一个个体的不同活动模式。

## 11.3 生命运行频率

还要避免让系统为了表现自主性而持续消耗大量 Token。

建议设计不同运行频率：

| 运行类型   | 触发方式           |
| ------ | -------------- |
| 实时反应   | 用户交互、传感器事件     |
| 短期活动   | 待办、目标进展、当前任务   |
| 周期活动   | 低频回顾、知识整理      |
| 事件触发反思 | 重大经历、判断错误、关系变化 |
| 长期发展   | 人格、认知、技能的阶段性评估 |

这需要一个统一调度器。

它根据重要程度、资源预算、当前权限和运行条件决定何时执行。

自主性并不意味着必须始终保持模型运行。

# 十二、项目从开始到结束：重新规划九个阶段

这次不再使用 Species 路线。

我建议采用以下路线：

# AI Companion · Individual Roadmap

一个人工个体从诞生到独立发展的完整工程路线

1. 当前阶段

   Phase 0 · Existence & Design

   定义人工个体、完整人类参照模型、生命原则、人格、记忆、自主性和系统边界。

   交付：完整顶层设计与架构基线。
2. Phase 1 · Genesis & Identity

   实现个体诞生、唯一身份、初始人格、自我模型和持久化身份。

   验收：系统重启、模型更换之后，仍能恢复同一个个体。
3. Phase 2 · Personality & Cognition

   实现人格、思维倾向、认知、判断、价值观和元认知。

   验收：具有独立人格和可持续的认知行为。
4. Phase 3 · Memory & Autobiography

   实现多层记忆、事件记录、记忆巩固、检索、纠错、遗忘和自传体历史。

   验收：能够准确延续过去的重要经历。
5. Phase 4 · Emotion & Relationships

   实现情绪、情感倾向、关系、羁绊和共同历史。

   验收：能够维持跨时间的关系连续性。
6. Phase 5 · Embodiment & Perception

   实现虚拟身体、视觉、听觉、环境感知和多种行动接口。

   验收：能够通过不同媒介认识环境。
7. Phase 6 · Autonomous Life

   实现内部动机、自主目标、主动学习、独立活动和长期计划。

   验收：没有用户直接指令时，仍能够开展有依据的内部活动。
8. Phase 7 · Evolution & Capability Creation

   实现人格适应、认知变化、技能学习、工具发现和工具创造。

   验收：能力与人格变化具有可追溯的经历和证据。
9. Phase 8 · Complete Companion Ecosystem

   完善 WebUI、桌面、移动端、语音、多模态、长期运行、权限、安全和生命历程展示。

   验收：成为一个可长期运行、能够持续发展、具备多媒介交互能力的完整产品。

这里有一个重要建议：

不要把 Phase 8 理解为生命本体直到最后才出现。

Phase 1 就应该已经有一个可以运行的个体。

之后的每个阶段都是让它逐渐获得更完整的生命能力。

例如：

Phase 1 的个体可能还没有复杂情感，但它已经拥有身份和自我模型。

Phase 3 的个体已经能够延续过去的经历。

Phase 6 的个体开始拥有真正的自主活动。

Phase 8 则是将它的完整能力转化为成熟的交互产品。

# 十三、如何使用 Codex、Claude Code、DeepSeek Harness？

必须建立一个统一的领域模型。

但必须建立一个原则：

Codex 负责维护项目的统一设计，其他 Agent 在明确的模块边界内工作。

## 13.2 每一个阶段都必须有真正的验收

例如：

人格模块不能只验收「模型回答得像不像」。

- 是否保持核心人格连续性。
- 是否能够在不同情境中调整行为。
- 是否会因短期情绪而错误改变长期人格。
- 是否能够解释重要的人格变化。
- 是否能够保留过去的人格版本。

记忆模块不能只验收「能不能记住」。

还需要测试：

- 是否区分真实经历与外部知识。
- 是否会混淆人物。
- 是否会编造历史。
- 是否能够修正错误。
- 是否能够跨模型恢复。

自主模块不能只验收「会不会主动发消息」。

还需要测试：

- 是否具有合理的目标来源。
- 是否能判断是否值得行动。
- 是否能在没有用户输入时开展适度活动。
- 是否会重复执行无意义任务。
- 是否能够停止、暂停和恢复。
- 是否会超出授权范围。

这才是完整工程。

特别是：

1. 什么构成一个持续存在的人工个体？
2. 完整人类生命模型的边界是什么？
3. 人格、情绪、情感、动机之间如何划分？
4. 记忆如何影响人格和自我认知？
5. 自主性如何产生和持续？
6. 身体与交互媒介如何解耦？
7. 演化如何发生，如何避免无依据的随机变化？
8. 系统如何保证身份连续性？
9. 如何判断某个模块真正实现了预期能力？
10. 哪些能力可以现在实现，哪些需要实验，哪些仍属于开放科学问题？

我建议让 Codex 先以首席生命系统架构师的身份完成这些工作。
